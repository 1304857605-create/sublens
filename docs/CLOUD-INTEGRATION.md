# 云端 ASR / MT 接入指南

> 本仓库的默认链路是**离线可跑的模拟器**(脚本化 ASR + 短语表 MT), 目的是让任何人
> clone 下来一条命令就能看到完整效果。真正上线要接云端服务, 本文说明接哪里、怎么接。

---

## 1. 接入点

所有外部能力都收敛在四个接口后面, 接云只需要新增实现类, **上层流水线一行不用改**:

| 接口 | 文件 | 云端实现要做什么 |
|---|---|---|
| `AsrBackend` | `include/sublens/asr.hpp` | 建立流式连接, 上传 PCM, 把 partial 转成 `AsrPartial` |
| `MtBackend` | `include/sublens/mt.hpp` | 发文本、收译文, 转成 `MtResult` |
| `IAudioSource` | `include/sublens/audio_source.hpp` | 真机麦克风(AAudio/Oboe) |
| `HudRenderer` | `include/sublens/hud.hpp` | 真机显示(GLES / 厂商 HUD API) |

`CloudAsrBackend` 已经有骨架(未配置 endpoint 时 `start()` 返回 false 并打日志),
照着它补网络层即可。

---

## 2. 流式 ASR 协议要点

以主流云厂商的实时语音识别(WebSocket)为例:

```text
端                                         云
 |-- WS 握手 (鉴权 header: api-key / token) ->|
 |<--------------- 握手完成 -------------------|
 |-- 开始指令 {format:pcm, sample_rate:16000,
 |            channels:1, intermediate:true} ->|
 |<-------------- 确认 -----------------------|
 |-- 音频帧(每 100ms 一包, PCM16) ----------->|
 |<-- partial {text:"我想去火", final:false} --|
 |<-- partial {text:"我想去火车站", final:false}|
 |<-- final   {text:"我想去火车站。", final:true}|
 |-- 结束指令 ------------------------------->|
```

实现时必须处理的四件事:

1. **鉴权与重连**: token 过期/网络抖动时指数退避重连, 重连期间音频先缓冲(最多 2s),
   超时则丢弃并给 HUD 打"网络不稳"提示, 而不是静默卡住;
2. **partial 语义**: 协议里的 partial 是**整句当前假设**, 不是增量。不要把多个 partial
   拼起来, 否则文字会重复;
3. **final 与超时**: 有些厂商在静音时不回 final, 需要客户端设 `max_wait_final_ms`
   (如 800ms) 主动收尾, 否则这句话永远不会提交给翻译;
4. **并发句**: 同一时刻可能有多句在飞(用户连续说话), `utt_id` 必须全程透传,
   调度器靠它区分句子。

## 3. 翻译接入要点

| 模式 | 延迟 | 用法 |
|---|---|---|
| 同步 HTTP | 200~500ms | 简单, 但每句一次往返, 只适合"草稿行都关掉"的省电模式 |
| 流式 HTTP/2 或 SSE | 80~200ms 首包 | 推荐: 边收边追加, 主行可以逐片段长出来 |
| 端侧小模型 | 5~40ms | 断网兜底, 质量换延迟 |

产品策略建议(本项目默认):

- **正式翻译**(已稳定片段)走高质量模型, 允许 200ms;
- **草稿翻译**(未确认尾串)走快模型或端侧小模型, 超时就丢, 不追求质量;
- 同一句的多次草稿请求要**合并/去抖**(本仓库 `draft_throttle_ms=150`), 否则云端按 token 计费会失控。

## 4. 成本估算(按公开价目量级)

以中英对话、每天 2 小时有效说话为例:

| 项 | 用量 | 量级 |
|---|---|---|
| ASR | 2h 音频/天 | 按分钟计费, 通常每天几元 |
| MT | 约 3 万字/天 | 按字符计费, 每天几元 |
| 流量 | 16kHz×16bit = 32KB/s ≈ 115MB/h | 手机热点也能扛 |

**优化点**: 端侧 VAD 只上报有效语音(本设计已做), 通常能省掉 40~60% 的音频上传量;
草稿翻译只对"未确认尾串"触发, 且带节流, 是成本与体验的关键平衡点。

---

## 5. 隐私与合规

- 眼镜录的是**他人对话**, 必须提供明显的录音指示灯/提示音与物理开关;
- 云端方案要写明数据留存策略; 涉密场景应走端侧模型;
- 部分国家/地区对公共场所录音有额外要求, 产品化前要核对。

---

## 6. 没有网络时怎么办

本仓库的模拟器链路本身就是一个离线兜底形态:

```bash
./build/sublens_demo en2zh --fast   # 无网络、无模型也能完整跑通
```

要换成真实离线模型, 需要:

| 组件 | 推荐 | 备注 |
|---|---|---|
| 端侧 ASR | whisper.cpp (tiny/base, int8 量化) | 中英双语, 树莓派级算力可跑 |
| 端侧 MT | 量化 NLLB-200-distilled / opus-mt | 质量一般, 但断网可用 |
| 推理后端 | ONNX Runtime Mobile / NCNN / MNN | 都有 C++ API, 接口不变 |

这也是本仓库坚持"核心纯 C++、零依赖"的原因: 端侧模型都是 C/C++ 生态,
Java/Kotlin 层只做壳。
